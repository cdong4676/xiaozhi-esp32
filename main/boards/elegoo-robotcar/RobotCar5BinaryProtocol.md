# RobotCar5 二进制协议格式规范

## 协议概述

二进制协议格式，用于替代原有的JSON文本协议，提供更高效的数据传输和处理性能。这里的协议只是从app发送到机器人的协议，机器人收到协议后，需要解析协议，根据协议类型，调用对应的方法处理协议。

## 协议结构

### 基本包格式
```
+--------+--------+--------+--------+--------+--------+--------+--------+
| Header | Header |      Length (4 bytes)          |  Type  |  Data  |
|  0xFF  |  0x55  |  Byte0 | Byte1 | Byte2 | Byte3 |  Byte  |  ...   |
+--------+--------+--------+--------+--------+--------+--------+--------+
   2字节              4字节              1字节    变长
```

- **Header**: 固定协议头 `0xFF 0x55` (2字节)
- **Length**: 数据包总长度（包含类型字节），小端序 (4字节)
- **Type**: 协议类型或命令类型 (1字节)
- **Data**: 具体数据内容 (变长)

### 协议类型定义

```csharp
public enum ProtocolType : byte
{
    VIDEO_FRAME = 0x01,    // 视频帧数据
    COMMAND = 0x02,        // 命令数据
    STATUS = 0x03,         // 状态数据
    HEARTBEAT = 0x04,      // 心跳数据
    VOICE = 0x05,          // 语音数据
}
```

## 命令协议格式 (Type = 0x02)

### 命令类型定义

```csharp
public enum BinaryCommandType : byte
{
    // 基础命令
    EXECUTE_MODE = 0x01,           // 执行模式
    EXECUTE_MOVE = 0x02,           // 执行移动
    EXECUTE_MOTOR_CONTROL = 0x03,     // 执行电机控制
    EXECUTE_CHANGE_SERVO = 0x04,    // 执行舵机控制
    EXECUTE_SENSING_DATA = 0x05,        // 执行获取数据
}

### 具体命令格式

#### 1. 执行模式命令 (EXECUTE_MODE = 0x01)
```
+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                    |  Type  |  Mode  |
|                                                             |  0x01  | 1 byte |
+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，用于命令追踪和响应匹配
- **Type**: 命令类型BinaryCommandType.EXECUTE_MODE 0x01
- **Mode**: 模式值 (0=待机, 1=避障，2=循迹，3=跟随)

#### 2. 执行移动命令 (EXECUTE_MOVE = 0x02)
```
+--------+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                    |  Type  |  Dir   | Speed  |
|                                                             |  0x02  | 1 byte | 1 byte |
+--------+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，用于命令追踪和响应匹配
- **Type**: 命令类型BinaryCommandType.EXECUTE_MOVE 0x02
- **Dir**: 方向值 (0=停止, 1=前进, 2=后退, 3=左转, 4=右转, 5=左前, 6=右前, 7=左后, 8=右后)
- **Speed**: 移动速度 (0-255)

#### 3. 电机控制命令 (EXECUTE_MOTOR_CONTROL = 0x03)
```
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                    |  Type  | Motor  |  Dir   | Speed  |
|                                                             |  0x03  | 1 byte | 1 byte | 1 byte |
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，用于命令追踪和响应匹配
- **Type**: 命令类型BinaryCommandType.EXECUTE_MOTOR_CONTROL 0x03
- **Motor**: 电机编号 (0=全部，1=左，2=右)
- **Dir**: 方向 (0=不处理,1=正转, 2=反转)
- **Speed**: 速度 (0-255)

#### 4. 舵机控制命令 (EXECUTE_CHANGE_SERVO = 0x04)
```
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                    |  Type  | Servo  |     Angle      |
|                                                             |  0x04  | 1 byte |    2 bytes     |
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，用于命令追踪和响应匹配
- **Type**: 命令类型BinaryCommandType.EXECUTE_CHANGE_SERVO 0x04
- **Servo**: 舵机编号 (1-2)
- **Angle**: 角度值 (0-180)

#### 5. 传感器读取命令 (EXECUTE_SENSING_DATA = 0x05)
```
+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                    |  Type  | Sensor |
|                                                             |  0x05  | 1 byte |
+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，用于命令追踪和响应匹配
- **Type**: 命令类型BinaryCommandType.EXECUTE_SENSING_DATA 0x05
- **Sensor**: 传感器编号 (1=拾取检测, 2=超声波, 3=红外左, 4=红外中, 5=红外右)

### Command ID 说明

Command ID 是一个6字节的唯一标识符，用于：
- **命令追踪**: 每个发送的命令都有唯一的ID，便于追踪命令执行状态
- **响应匹配**: 响应数据包含相同的Command ID，确保响应与请求正确匹配
- **并发处理**: 支持多个命令并发执行，通过ID区分不同的命令
- **错误处理**: 当命令执行失败时，可以通过ID准确定位问题命令

Command ID 生成建议：
- 使用时间戳 + 随机数的组合
- 或使用递增序列号 + 设备标识
- 确保在合理时间窗口内的唯一性

### 响应数据格式


public enum ResponseCommandType : byte
{
    // 基础命令
    RESPONSE_NORMAL = 0x01,           // 普通响应
    RESPONSE_SENSING_DATA = 0x02,           // 获取传感器数据响应
}

#### 通用响应格式
```
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                    |  Type  | Status |
|                                                             |  0x02  | 1 byte |
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，与对应的请求命令ID匹配
- **Type**: 响应类型 ResponseCommandType.RESPONSE_NORMAL 0x01
- **Status**: 状态码 (0=成功, 1=失败, 2=超时)

#### 传感器数据响应
```
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
|                    Command ID (6 bytes)                      |  Type  | Sensor |      Value      | Status |
|                                                              | 0x0E-  | 1 byte |       2 bytes   | 1 byte |
|                                                              | 0x11   |        |      (ushort)   |        |
+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+--------+
```
- **Command ID**: 6字节唯一标识符，与对应的请求命令ID匹配
- **Type**: 响应类型 ResponseCommandType.RESPONSE_SENSING_DATA 0x02
- **Sensor**: 传感器编号(1=拾取检测, 2=超声波, 3=红外左, 4=红外中, 5=红外右)
- **Value**: 传感器数值 (ushort, 小端序)
- **Status**: 状态码 (0=正常, 1=错误, 2=超时)

## 协议优势

### 1. 性能优势
- **数据量减少**: 二进制格式比JSON文本格式减少60-80%的数据量
- **解析速度**: 二进制解析比JSON解析快5-10倍
- **内存占用**: 减少字符串处理的内存分配

### 2. 可靠性优势
- **类型安全**: 强类型定义，减少数据类型错误
- **校验机制**: 可以添加CRC校验确保数据完整性
- **版本兼容**: 预留扩展字段，便于协议升级

### 3. 扩展性优势
- **命令分类**: 按功能模块分类命令类型，便于管理
- **参数灵活**: 支持不同长度的参数组合
- **响应机制**: 支持命令响应和状态反馈
```
